# Ops-Agent v1 TUI 设计

> 日期：2026-10-13
> 状态：已确认。实现计划见 `docs/superpowers/plans/2026-10-13-ops-agent-v1-tui.md`。
> 范围：v1 主界面、设置页、对话能力和按键。本文件不改代码。
> 依据：`docs/superpowers/specs/2026-10-13-ops-agent-product-roadmap-design.md`

## 1. 主界面

v1 打开后只有任务队列和对话两个工作区。

```text
┌ 状态栏：模型名 · webhook 开/关 · 当前仓库 · 任务数 ─────────────┐
├ 任务队列                          │ 对话                        │
│ ○ owner/repo#45 执行中            │                            │
│ ● owner/repo#46 已停住            │                            │
│   阶段：verifying                 │                            │
│   日志：最近 3 行                 │                            │
│   原因：连续 3 次测试失败          │                            │
│   PR：—                           │                            │
│ ○ owner/repo#47 排队中            │                            │
│                                   ├────────────────────────────┤
│                                   │ 输入                        │
└ s 设置 · j/k 选任务 · Esc 退出 ───────────────────────────────┘
```

左侧是任务队列。没选中的任务只占一行：来源仓库、编号、阶段。选中的那一条在原位展开四行：

- 阶段
- 最近 3 行日志
- 停住原因
- draft PR 地址

没有停住原因或还没有 PR 时，对应行写「—」。未完成任务排在前面。状态为完成或取消的任务留在列表里，排在未完成任务后面。

右侧对话不显示某一条任务的展开详情。输入框只在右侧底部。

状态栏只显示当前值：模型名、webhook 开或关、当前仓库、任务数。不在状态栏里改这些值。

## 2. 设置页

主界面输入框为空时按 `s` 进入设置页。设置页盖住任务和对话。设置页里按 `Esc` 回到主界面，不退出程序。

设置页只有三项，每一项显示当前值，并写明对应的配置文件字段：

- 模型：当前模型名，以及服务是否可达。
- Webhook：开或关，以及监听地址。
- 代理：开或关，以及代理地址。

保存写入配置文件，并立刻作用于当前进程。之后的模型请求、webhook 接收和代理走新值。任务队列和任务详情不在这一页编辑。合并、关闭 Issue、force push 也不在这一页执行。

## 3. 对话

右侧对话可以查状态，也可以执行操作。

查状态包括：某条任务为什么停、队列里有几条、模型是否可达、webhook 是否开着。解释失败时，使用该任务的阶段、最近 3 行日志和停住原因。

对话可以改变任务和配置：

- 停止一条任务。任务留在列表中，停住原因写「用户停止」，不再继续执行。
- 重试一条任务。沿用同一条任务再跑一次闭环，不新建第二条任务。
- 跳过一条任务。任务状态改为取消，不再执行。
- 修改模型、webhook、代理。效果与设置页保存相同：写入配置文件，并作用于当前进程。
- 合并 PR、关闭 Issue、force push。

停止、重试、跳过和修改配置在用户说出对象后执行。合并 PR、关闭 Issue、force push 不能直接执行。

高风险确认发生在右侧对话里，不另开菜单。同时只有一条待确认动作。对话先写出将要执行的动作和对象，对象包括仓库、编号，以及涉及的分支或 PR。用户下一句输入去掉首尾空白后是「确认」，才执行。其他内容都视为不执行，并保留在对话记录里。新的高风险请求会替换尚未确认的那一条，对话里说明上一句已取消。执行结果写回右侧对话，成功或失败都写明对象。

空输入不触发动作。自动开 draft PR 仍由任务队列完成。一句话不直接改代码，也不直接开 PR。

`/mode`、`/model`、`/proxy`、`/webhook` 不再作为主界面菜单。这些配置用自然语言说，或者按 `s` 进入设置页。

## 4. 按键

| 位置 | 输入框 | 按键 | 结果 |
| --- | --- | --- | --- |
| 主界面 | 空 | `j` / `k` | 移动左侧选中任务，选中项立刻展开 |
| 主界面 | 有文字 | `j` / `k` | 只进入文字，不移动任务 |
| 主界面 | 空 | `s` | 打开设置页 |
| 主界面 | 有文字 | `s` | 只进入文字 |
| 主界面 | 空 | `Esc` | 退出程序 |
| 设置页 | — | `Esc` | 关闭设置页，回到主界面 |

## 5. 主界面不再保留

- `/mode`、`/model`、`/proxy`、`/webhook` 菜单。
- 库验收列表，以及左右切换验收栏的按键。
- 用一句话直接改代码或开 PR。

v1 的全部界面是左侧任务队列、右侧对话、设置页。

## 6. 与路线图的关系

路线图规定自动队列不合并 PR、不关闭 Issue、不 force push。本设计不改变这条自动边界。

人通过右侧对话确认后，对话可以执行这三件事。未确认时不执行。这是路线图里「由人来做」在 v1 界面上的落点。

## 7. 自检

- 最近日志固定为 3 行。
- 高风险确认词固定为去掉首尾空白后的「确认」。
- 停止、重试、跳过的结果分别是「用户停止」、同一条任务再跑一次、状态改为取消。
- 自动队列与对话确认的边界写在第 6 节，两处不互相放宽。
